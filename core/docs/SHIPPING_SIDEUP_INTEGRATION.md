# تكامل الشحن مع SideUp – دليل أدمن الموقع (Tenant Admin)

هذا الملف يوضح **السيناريو الكامل** لاستخدام تكامل الشحن مع SideUp بحيث **أدمن الموقع (Tenant Admin)** يقدر يفعّل الشحن ويستخدمه مع طلبات المنتجات.

---

## 1. نظرة عامة

- **من يستخدم:** أدمن الموقع (Tenant) — كل متجر/موقع له إعداداته الخاصة.
- **ماذا يفعل التكامل:** يربط طلبات المنتجات (Product Orders) بمنصة SideUp لإنشاء شحنات، تتبعها، وتحميل ملصقات الشحن.
- **أين الإعدادات:** إعدادات SideUp **لكل تيننت على حدة**.
- **طرق الربط:** يمكن الربط بإحدى الطريقتين:
  - **API Key:** إدخال Base URL و API Key من لوحة SideUp.
  - **Email + Password (Legacy):** إدخال إيميل وباسورد حساب SideUp، أو **تحميل ملف JSON قديم** يحتوي على: `email`, `password`, واختياريًا `base_url`. النظام يستخدمها لتسجيل الدخول واستلام توكن تلقائيًا.

---

## 2. السيناريو المفترض خطوة بخطوة

### المرحلة الأولى: تفعيل وإعداد SideUp (مرة واحدة لكل متجر)

| الخطوة | ماذا يفعل أدمن الموقع | أين |
|--------|------------------------|-----|
| 1 | يسجّل الدخول إلى **لوحة إدارة الموقع (Tenant Admin)** على دومين المتجر (مثل `mystore.eazola.com`). | المتصفح |
| 2 | يفتح صفحة **إعدادات SideUp**: من **القائمة الجانبية** → **SideUp Settings** (أو الرابط المباشر: `https://[دومين-المتجر]/admin-home/shipping/sideup`). | نفس الدومين |
| 3 | يختار **طريقة الربط:** إما **API Key** (يدخل Base URL + API Key) أو **Email + Password (Legacy)** (يدخل الإيميل والباسورد، أو يرفع ملف JSON قديم بالمفاتيح: `email`, `password`, واختياريًا `base_url`). | نموذج الإعدادات |
| 4 | يفعّل الخيار **Enable SideUp Integration**. | سويتش في نفس الصفحة |
| 5 | يضغط **Save Settings**. | زر الحفظ |
| 6 | (اختياري) يضغط **Test Connection** للتأكد أن الربط شغال. | زر في نفس الصفحة |

بعد هذه الخطوات يصبح التكامل **مفعّلاً لهذا المتجر فقط**. متاجر أخرى تحتاج نفس الإعداد على لوحة كل متجر.

---

### المرحلة الثانية: طلبات المنتجات والشحن

#### السيناريو (أ): إنشاء شحنة تلقائياً عند إكمال الطلب

| الخطوة | ماذا يحدث في النظام |
|--------|----------------------|
| 1 | العميل يطلب منتجات من المتجر ويكمل الطلب. |
| 2 | أدمن الموقع يغيّر **حالة الطلب** إلى **Complete** من صفحة إدارة الطلبات. |
| 3 | النظام يتحقق: هل SideUp مفعّل لهذا التيننت؟ وهل للطلب شحنة مسبقاً؟ |
| 4 | إذا نعم (مفعّل) ولا (مافيش شحنة): يتم **إنشاء شحنة تلقائياً** عند SideUp وحفظها في جدول `shipments`. |
| 5 | إذا فشل الإنشاء (مثلاً خطأ من API): يتم تسجيل التحذير في الـ Log ولا يتم إلغاء تغيير حالة الطلب. |

يعني: **أدمن الموقع لا يضغط أي زر شحن هنا** — مجرد تغيير الحالة إلى "Complete" يكفي لتفعيل الإنشاء التلقائي (إن كان الإعداد صحيحاً).

#### السيناريو (ب): إنشاء شحنة يدوياً من صفحة الطلب

| الخطوة | ماذا يفعل أدمن الموقع |
|--------|------------------------|
| 1 | يفتح **تفاصيل الطلب** من: إدارة الطلبات → اختيار الطلب → عرض التفاصيل. |
| 2 | في أعلى صفحة التفاصيل يجد قسم **Shipping / SideUp**. |
| 3 | إذا **لم تكن هناك شحنة** يظهر زر **"Create SideUp Shipment"**. |
| 4 | يضغط الزر → النظام يرسل بيانات الطلب (العنوان، المنتجات، COD إن وُجد) إلى SideUp وينشئ الشحنة. |
| 5 | بعد النجاح تظهر أزرار **View Tracking** و **Download Label** (إن وفرها SideUp). |

هذا مفيد لو:
- الطلب كان Complete قبل تفعيل SideUp، أو
- الإنشاء التلقائي فشل سابقاً، أو
- تريد إنشاء شحنة لطلب معيّن يدوياً.

---

### المرحلة الثالثة: بعد إنشاء الشحنة

| ماذا يظهر لأدمن الموقع | الاستخدام |
|------------------------|-----------|
| **View Tracking** | يفتح رابط التتبع من SideUp (في تاب جديد). |
| **Download Label** | يحمّل ملصق الشحن إن رجعه الـ API. |

البيانات (tracking number, status, label_url, tracking_url) تُحفظ في جدول `shipments` وترتبط بالطلب عبر `order_id`.

---

## 3. الشروط حتى يعمل التكامل

- موديول **Shipping** (اللي فيه SideUp) مفعّل ومهيأ للمشروع.
- موديول **Product** مفعّل (طلبات المنتجات).
- في قاعدة بيانات الـ **Tenant**:
  - جداول `shipping_accounts` و `shipments` موجودة (هجرة الـ tenant تشمل موديول Shipping).
- أدمن الموقع أدخل **API Key** و **Base URL** صحيحين وفعّل **Enable SideUp Integration**.

---

## 4. الروابط والأماكن المهمة (لأدمن الموقع)

| الغرض | الرابط أو المكان |
|-------|------------------|
| إعدادات SideUp | القائمة الجانبية → **SideUp Settings**، أو مباشرة: `https://[دومين-المتجر]/admin-home/shipping/sideup` |
| كل الطلبات | من القائمة: إدارة الطلبات / Product Orders (حسب تسمية القائمة عندك). |
| تفاصيل طلب واحد | من قائمة الطلبات → اختيار الطلب → صفحة التفاصيل (نفس الصفحة اللي فيها زر Create SideUp Shipment). |

---

## 5. ملخص سريع لأدمن الموقع

1. **مرة واحدة:** ادخل على `/admin-home/shipping/sideup` وضبط API Key و Base URL وفعّل التكامل واحفظ، واختبار الاتصال إن أردت.
2. **مع كل طلب:**  
   - إما تغيير حالة الطلب إلى **Complete** فيصبح إنشاء الشحنة **تلقائياً** (إن كان الإعداد مضبوطاً).  
   - أو من صفحة تفاصيل الطلب اضغط **Create SideUp Shipment** لإنشاء الشحنة **يدوياً**.
3. **بعد إنشاء الشحنة:** استخدم **View Tracking** و **Download Label** من نفس صفحة الطلب.

بهذا يكون السيناريو الكامل واضحاً لأدمن الموقع لاستخدام الشحن مع SideUp.

---

## 6. للمطورين (اختياري)

- **إضافة رابط SideUp في السايدبار:** حالياً صفحة إعدادات SideUp تُفتح بالرابط المباشر فقط. لو أردت إظهارها تحت قائمة "Shipping Manage" (موديول ShippingModule)، يمكن إضافة عنصر قائمة يوجّه إلى `tenant.admin.shipping.sideup.settings` في `SidebarMenuHelper::tenant_shipping_settings_menus()` أو في إعدادات الموديول.
- **الإنشاء التلقائي:** يحدث داخل `Modules\Product\Http\Controllers\OrderManageController` عند تحديث حالة الطلب إلى `complete` عبر الدالة `autoCreateSideupShipmentIfEnabled()`.
- **الجداول (Tenant DB):** `shipping_accounts` (إعدادات الحساب)، `shipments` (ربط الطلب بالشحنة وبيانات التتبع).
